# cn-math-notation 设计草案

日期：2026-11-19　状态：**草案；第一期整数竖式的写法已按沪教版样本核对（§11）**

**定位（维护者 2026-11-19 定）**：中国中小学数学写法库，作为 **KaTeX 的扩展**。普通公式一律交给 KaTeX；本库只做通用工具画不了的课堂写法，要求简单、适合孩子学习。

**范围**：竖式家族（整数与小数加减乘除、多项式竖式、综合除法）、短除法、分解质因数树状图、十字相乘法、递等式。第一期只做整数竖式。

## 0. 与 KaTeX 的关系

**写法用 LaTeX 命令**，在 `$...$` / `$$...$$` 里与普通公式混写：

```latex
$$\shushi{365+278}$$                         % 竖式，程序算出正确过程
$$\shushi[steps]{725\div 4}$$                % 逐步展示
$$\duanchu{36, 48}$$                      % 短除法
$$\shuzhuang{36}$$                        % 分解质因数树状图
$$\shizi{x^2+5x+6}$$                      % 十字相乘
\begin{dengshi}                           % 递等式
  & 25 \times (40 + 4) \\
= & 25 \times 40 + 25 \times 4 \\
= & 1100
\end{dengshi}
```

直写布局（孩子的错误过程等）用环境，沿用 LaTeX `array` 的 `&` 分列、`\\` 分行、`\hline` 画线，格内用小命令挂标记：

```latex
\begin{shushi}
   & 4\tui & 0\tui & 3 \\
 - & 1     & 6     & 7 \\ \hline
   & 3     & 4     & \err{6}
\end{shushi}
% \tui = 退位点，\jin{1} = 进位 1，\err{} = 标为错误
```

命令名**拼音为主、英文做别名**（维护者 2026-11-19 定）。两者完全等价，文档与示例用拼音：

| 拼音（主） | 英文别名 | 写法 |
|---|---|---|
| `\shushi` / `shushi` 环境 | `\vertical` / `vertical` | 竖式 |
| `\duanchu` | `\shortdiv` | 短除法 |
| `\shuzhuang` | `\factortree` | 分解质因数树状图 |
| `\shizi` | `\crossmul` | 十字相乘 |
| `dengshi` 环境 | `stepeq` | 递等式 |
| `\jin{1}` | `\carry{1}` | 进位标记 |
| `\tui` | `\borrow` | 退位点 |
| `\err{}` | `\err{}` | 标为错误（本身是英文缩写，不另设） |

**不设拼音首字母缩写**（维护者 2026-11-19 定：缩写多与 KaTeX/LaTeX 冲突，如 `\ss`=ß、`\j`=ȷ、`\t`=连音符，且树状图与十字相乘同为 `sz`）。只有全拼与英文别名两套。

~~英文别名的具体拼写 [待定]~~ **已结案（2026-11-27）**：最终写法以[使用说明的命令一览](../usage.md#命令一览)为准，上表是初稿（“环境”写法没有采用，实际都是命令形式）。英文别名：`\vertical`、`\stepeq`、`\shortdiv`、`\factortree`、`\crossmul`、`\synthdiv`；格子标记 `\carry`、`\borrow`、`\pad`、`\hl`、`\strike`（`\err`、`\shang`、`\chu` 不另设别名）。已核对全部 25 个命令名（6 个拼音主名、6 个英文别名、13 个格子标记）在 KaTeX 0.19.1 与 MathJax 4（加载全部宏包）里都未被占用，并写成回归测试（`packages/katex/test`、`packages/server/test/mathjax.test.ts`），升级 KaTeX / MathJax 时会报出新冲突。格子标记最要紧：KaTeX 会先展开 raw 参数里的宏，同名宏会把它们替换掉。`\hl` 在 LaTeX 的 soul 宏包里也表示高亮，意思一致，本库不面对 LaTeX，不算冲突。

**接入方式（已核实 KaTeX 0.19.1 包内容，2026-11-19）**：
- KaTeX 对外暴露 `__defineFunction`（注释：新增函数，产生解析树节点并有自己的 HTML / MathML 构建器）与 `__defineMacro`；官方 mhchem 扩展用的是 `__defineMacro`。
- KaTeX 本身**没有** `longdiv`、`\enclose` 之类命令，竖式无法只靠宏拼出来。
- 所以用 `__defineFunction` 注册本库命令：HTML 构建器嵌入本库渲染结果，MathML 构建器输出能对应的 MathML 子集。
- 风险：双下划线前缀，按惯例属不稳定接口 **[推论]**。对策：KaTeX 版本锁定在验证过的范围；适配层做薄；跨版本测试。退路：渲染前先扫出本库命令自己画、其余交给 KaTeX（兼容任意版本，但不能嵌进其他公式内部）。

**分包**：
- `core`：模型、生成器、SVG 渲染、朗读文字；不依赖 KaTeX。格子里的公式（如 `3x^2`）通过注入的“公式渲染器”接口画。
- `katex`：KaTeX 插件，注册命令，并把 KaTeX 作为 `core` 的公式渲染器。
- **更正（2026-11-25）**：原写“多数 Markdown 工具已内置 KaTeX，有 `katex` 包就够”，说过头了。KaTeX 插件只在**能控制 KaTeX 加载代码**的地方生效（自己的应用、自建网站）；Typora、Obsidian、GitHub 自带封闭的公式引擎，无法注册新命令。
- **Typora（维护者 2026-11-25 定）**：KaTeX 插件完成后，基于 typora-community-plugin 另写一个 Typora 插件（维护者已有 typora-plugin-plantuml 等经验）。已核实本机 Typora.app 内置的是 **MathJax4**（`Contents/Resources/TypeMark/lib/MathJax4`），不是 KaTeX，所以 Typora 插件直接用 `core` 渲染，不经 KaTeX 插件；接入方式见 §13（2026-11-26 实现）。
- 其他编辑器（Obsidian 等）以后按需各写插件，或提供“渲染成图片”的兜底。

以下 §1～§9 原为竖式的内部模型，仍适用于竖式家族与短除法；树状图、十字相乘、递等式不是格子结构，模型另写（见 §10）。

依据：
- 起源：一个家庭学习项目需要在错题和题目里展示竖式。最初的设想是竖式用带类型的代码块、结构化数据，由渲染器画出；小学三年级的重点就是笔算乘除，出题和展示孩子的计算过程都要用。
- MathML 3 §3.6 / MathML 4 草案 §3.6 / MathML Core（2026-11-19 核实）：竖式元素不在 Core，浏览器不原生渲染；结构可表达多数国内写法，但没有竖线、括号，不支持短除法、综合除法。
- 维护者要求：要考虑初中、高中的扩展；MathML 的默认写法不是国内习惯（加法进位写下标、减法退位打点）。

标注约定：**[推论]** 是 AI 的设计判断，未经实测或样本核对；**[待样本]** 须等沪教版样本确认。

## 1. 目标与不做

目标：
1. 写起来像 LaTeX：短、能手写，嵌在 Markdown 代码块里。
2. 覆盖小学到高中的竖式类写法（清单见 §6），新增写法主要是加“生成器”，模型与渲染器不动。
3. 写法样式可切换：默认沪教版，其他地区、其他教材作为样式预设。
4. 能画**任意过程**，包括孩子的错误过程（不只是程序算出的正确过程）。
5. 可导出 MathML（能对应的子集）。

不做：
- 普通公式（交给 KaTeX）。
- 几何图形、数轴、钟面（另议）。
- 出题、判对错（属计算题引擎 B，待定）。

## 2. 分层

```
 文本写法（人写）          JSON（机器写，例如将来的计算题引擎）
      │                          │
      ▼                          │
 解析 ──► 语义式？──是──► 生成器 ──┤
      │                          │
      └──否（直写布局）──────────►┤
                                 ▼
                           布局模型（Layout）  ◄── 本文主体
                                 │
                  样式预设（cn-hujiao 等）
                                 │
                 ┌───────────────┼───────────────┐
                 ▼               ▼               ▼
              SVG 渲染      朗读文字描述      MathML 导出（子集）
```

- **语义式**：只写算式，如 `403-167`，由生成器算出完整的正确过程。
- **直写布局**：逐行写出格子内容和标记，用于孩子的错误过程、课本上的特殊写法、生成器还不支持的写法。
- 两条路最终都产出同一个布局模型；渲染器只认布局模型。

**[推论]** “朗读文字描述”是额外收益：给孩子用的界面常需要朗读，竖式画成图后屏幕阅读器读不出，所以渲染时同时生成一段可读文字（“三百六十五加二百七十八，个位五加八得十三，写三进一……”）。

## 3. 布局模型

### 3.1 坐标

- **列号**是整数，以个位为 0，向左（高位）为正，向右（小数位）为负：百位 2、十位 1、个位 0、十分位 −1。
  与 MathML 的 `position`（正数向高位）方向一致，便于导出。
- **小数点**不占列，是挂在“第 0 列和第 −1 列之间那条格线”上的标记。
  **[样本已核，§11]** 课本里小数点与数字间距相同，等于占一列。改回 MathML 做法：小数点占一列（列宽可略窄），列号仍以个位为 0，小数点列不计号、由渲染器插在第 0 与 −1 列之间。
- **行号**自上而下，从 0 开始。

### 3.2 元素

| 元素 | 作用 | 主要字段 |
|---|---|---|
| `Figure` | 一个完整竖式 | `kind`（add / sub / mul / longdiv / shortdiv / polydiv / synthdiv / custom）、`rows`、`rules`、`brackets`、`steps`、`style`、`meta` |
| `Row` | 一行 | `role`（operand / result / partial / step / remainder / quotient / divisor）、`cells`、`operator`（行首运算符，如 `+` `×`）、`shift`（整体左右移的列数） |
| `Cell` | 一格 | `col`、`content`（见 3.3）、`marks`、`decor` |
| `Mark` | 格子周围的小标记 | `role`（carry / borrow / note / hint）、`content`、`at`（九方位，可省）、`size`（默认 small） |
| `Rule` | 线 | `dir`（h / v）；横线：`afterRow`、`fromCol`、`toCol`、`overhang`；竖线：`betweenCols`、`fromRow`、`toRow`；`weight` |
| `Bracket` | 除法括号 | `type`（longdiv / shortdiv）、覆盖的行列范围 |
| `Step` | 逐步展示的一步 | `id`、`reveals`（本步出现的元素引用）、`say`（这一步的朗读文字） |

**关键设计：标记存“角色”，位置交给样式。**
`Mark` 只写 `role: carry`，不写位置；沪教版样式规定加法进位画在哪一行、哪个方位、多大。课本换写法，只换样式预设，数据不动。需要例外时，`at` 显式覆盖。
这正是 MathML 的痛点：它把 `location` 写死在数据里，所以“不是国内习惯”只能改数据。

**和 MathML 的差别**（有意为之）：
- 进位挂在**它所属的格子**上，而不是像 `mscarries` 那样挂在“下一行”。
- 有竖线与括号（短除法、综合除法、长除法的括号必需）。
- 有 `Step`，可逐步展示、做动画、朗读。

### 3.3 格子内容

| 类型 | 例 | 说明 |
|---|---|---|
| `digit` | `7` | 一位数字 |
| `term` | `3x^2`、`-5` | 一项，整体占一列；内部用 LaTeX 子集，交给 KaTeX 排 **[推论]** |
| `text` | `余` | 少量文字 |
| `blank` | | 占位但不显示（多项式缺项、对齐用） |
| `box` | `□` | 填空格，给出题用 |

### 3.4 装饰（decor）

划掉（`strike`：斜、反斜、竖、横，可叠加，沿用 MathML 的四种）、圈、框、**高亮**（语义色：`error` / `focus`），用来标出孩子出错的那一位。

### 3.5 错误过程

- 直写布局：孩子怎么写就怎么记，渲染器不校验对错。
- 语义式 + 声明孩子答案，如 `403-167=346`：生成器只能画正确过程，无法知道孩子怎么算的，所以只把结果行标为 `error` 高亮，不编造过程。
- **预留钩子**：`bug=<规则名>` 让生成器按某种错误做法生成过程（规则来自将来的错误做法库）。B 未定，本组件只预留字段，不实现。

## 4. 文本写法（初稿，已被 §0 的 LaTeX 命令写法取代，保留作对照）

原设想 Markdown 里用代码块，语言名 `shushi`。

### 4.1 语义式

````markdown
```shushi
365 + 278
```

```shushi style=cn-hujiao steps
725 ÷ 4
```

```shushi
短除 36 48          # 求最大公因数时的短除法
```

```shushi
(x^2 + 3x + 2) ÷ (x + 1)
```
````

选项：`style=`（样式预设）、`steps`（逐步展示）、`show=`（只画到某一步）、`bug=`（预留）。

### 4.2 直写布局

一行一行写，空格分列，右对齐到个位；`^` 开头的行是挂在上一行的标记行；`---` 是横线。

````markdown
```shushi layout
    4  0  3
^   ·  ·          # 退位点（role=borrow），挂在被减数上
-   1  6  7
---
    3  4  6  !    # 行尾 ! 表示整行高亮为 error（孩子的答案）
```
````

**[推论]** 直写语法是最不确定的部分：要兼顾好写和不歧义（标记对哪一列、多位数标记如“10”）。先用样本里的 10～15 个例子试写，再定。

### 4.3 JSON

机器生成或导出时用 JSON，结构与 §3 一一对应。文本写法解析后也得到同一份 JSON，测试对 JSON 断言。

## 5. 示例（布局用简化 YAML 示意）

### 5.1 加法连续进位：365 + 278 = 643

```yaml
kind: add
rows:
  - role: operand
    cells: [{col: 2, d: 3}, {col: 1, d: 6}, {col: 0, d: 5}]
  - role: operand
    operator: "+"
    cells:
      - {col: 2, d: 2, marks: [{role: carry, content: 1}]}   # 十位进到百位的 1
      - {col: 1, d: 7, marks: [{role: carry, content: 1}]}   # 个位进到十位的 1
      - {col: 0, d: 8}
  - role: result
    cells: [{col: 2, d: 6}, {col: 1, d: 4}, {col: 0, d: 3}]
rules:
  - {dir: h, afterRow: 1}
```

进位记在**第二个加数**的格子上；**[已定，§11.1]** 小字、红色、坐在横线上；位置支持“正下”（沪教版默认）与“左下”两种。

### 5.2 减法跨 0 退位：403 − 167 = 236

被减数百位、十位各带一个 `borrow` 标记，内容是点 `·`。
**[已定，§11.1]** 只打点：百位、十位各一个退位点，0 上方不另写 9。

### 5.3 两位数乘两位数：36 × 24 = 864

```
      3 6
  ×   2 4
  ───────
    1 4 4     ← partial，shift 0
    7 2       ← partial，shift 1（个位空着）
  ───────
    8 6 4
```

**[样本已核，§11]** 两位数乘两位数：部分积不写进位、第二行末尾不补 0（空着）。一位数乘的简写：进位与加法同样画在左下小字。

### 5.4 除法有余数：725 ÷ 4 = 181……1

```
          1 8 1        ← quotient 行，商对齐被除数的位
       ┌───────
     4 │ 7 2 5         ← divisor 在左，Bracket(longdiv) 包住被除数
         4
         ─             ← 每步一条短横线，fromCol/toCol 只覆盖该步
         3 2
         3 2
         ───
             5
             4
             ─
             1         ← remainder
```

除数占被除数左边的列（如 col 4），中间以括号隔开；商、被除数、各步在同一套列号里对齐。
**[样本已核，§11]** 沪教版确为除数在左、商在上，与 MathML 给中国标的 `righttop` 不符。

### 5.5 小数加法：3.45 + 12.6

按小数点对齐。**[样本已核，§11]** 被减数位数不够时补 0，补的 0 用红色虚线框标出（教学标记）；加法样本未见补 0。

### 5.6 短除法求最大公因数：36 和 48

```
   2 │ 36   48
     └──────────
   2 │ 18   24
     └──────────
   3 │  9   12
     └──────────
        3    4
```

每行左侧一条竖线 + 下方一条横线（`Bracket type: shortdiv`）。每个数是一个 `term`（整个数占一格，不按位拆）。**MathML 无法表达，导出时降级。**

### 5.7 初中：多项式长除法 (x² + 3x + 2) ÷ (x + 1) = x + 2

**2026-11-26 实现**（维护者定：乘法、长除法、分离系数法、直写都做；缺项留空位；沿用 `\shushi`，算式有字母即多项式）：
- 模型：新增格子内容 `{ kind: "term", text }`，列号 = 次数；渲染时列宽随项加宽、衬线斜体、不画数位虚线；MathML 把项拆成 `mo`/`mn`/`mi`/`msup`。
- 生成器 `polynomial/`：乘法第二个因式从低次项起每项一行 **[推论]**；长除法商写在同次项上方，每步减完写出余下各项，最后写余式 **[推论]**；商系数须为整数；`coefficients` 分离系数法（缺项写 0）。
- 直写：R10 `&` 分格（`parse-term-row.ts`），各格从右往左依次为 0、1、2… 次；第一格前可写 `\shang`、`\chu{…}`、运算符。
- 未做：两个字母、分数系数、孩子的答案、加减法竖式。

原始草稿：

结构与 5.4 相同，只是格子内容是 `term`（`x^2`、`+3x`、`+2`），列按次数对齐（x² 列、x 列、常数列）；缺项用 `blank`。生成器不同，模型不变。

### 5.8 高中：综合除法，除以 x + 1

**2026-11-26 实现**（维护者定：新命令 `\zonghe`，英文别名 `\synthdiv`；只做除以 x − a；竖线隔开余数；结果行 `result` 默认关；做直写 `\zonghe*`）：`synthdiv/`，算式解析与多项式长除法共用；`result` 选项解析与短除法共用（`result-option.ts`）。结果行“商 …，余数 …”与直写三行 `&` 分格的写法 **[推论]**。原题 `problem` 默认开（维护者 2026-11-26），在上方写 `(被除式) ÷ (除式)`，选项解析改为综合除法自己的 `synthdiv/options.ts`。

```
  -1 │  1    3    2
     │      -1   -2
     └──────────────
        1    2 │  0
```

用竖线、横线和 `term` 即可表达，最后一格前的竖线隔出余数。**MathML 无法表达。**

## 6. 写法清单与分期

| 期 | 写法 | 生成器 | MathML 导出 |
|---|---|---|---|
| 一 | 整数加、减（含连续进位、跨 0 退位）、乘（一位、两位）、除（一位除数、有余数） | 有 | ✓ |
| 一 | 直写布局（任意过程，含错误过程） | 不需要 | 部分 |
| 二 | 小数加减乘除；两位数除数 | 有 | ✓ |
| 二 | 短除法（分解质因数、最大公因数、最小公倍数） | 有 | ✗ 降级 |
| 三 | 多项式乘法、长除法；分离系数法 | 有 | ✓（按项对齐） |
| 三 | 综合除法、进制转换短除、辗转相除 | 有 | ✗ 降级 |

非格子类写法（见 §10）：递等式、树状图排第二期，十字相乘排第三期。

## 7. MathML 导出（2026-11-26 实现）

实现：`packages/core/src/mathml.ts`（`layoutToMathML`、`shushiToMathML`、`shushiLayoutToMathML`）；KaTeX 插件的隐藏 MathML 默认改为这套结构（`register` 的 `mathml: "label"` 可退回朗读文字）。

| 本模型 | MathML |
|---|---|

**兼容性实测（2026-11-26，维护者两轮截图）**：W3C elem-math polyfill（提交 38bd8d9）。
- 第一轮：`s`/`se`/`ne` 打断横线、整行错位。读源码发现：横线由每格下边框拼成，带进位的格子被撑高；`se`/`ne` 用 sub/sup 另有偏移。

- 对照页：`bun run mathml:preview`；横线对齐可用页面脚本逐格量下边框。
- **维护者 2026-11-26 定**：以当前对照页效果为准，不再为 polyfill 继续调整导出结构；之后有使用者反馈样式问题再调。导出保留进位语义（`mscarries`），对 polyfill 的唯一妥协是透明占位（`aria-hidden`）。

## 10. 非格子类写法（初稿）

### 10.1 递等式（2026-11-26 实现）

维护者定：**等号悬在算式左边**；**也做语义式**。

- 排版：TeX 的 `aligned` 环境，第一列放等号（右对齐）、第二列放算式（左对齐），第一行不写等号；行距 6pt。本库只产出 TeX，KaTeX 插件用 `__parse` 把它解析成节点嵌回当前公式，所以行内分数等照 KaTeX 排；核心包不依赖 KaTeX，也能给 MathJax（如 Typora）用。
- 语义式（`packages/core/src/dengshi/expr.ts`）：解析成语法树（括号保留原样），每步：有括号则只在括号里各自往前一步（算成一个数就去掉括号）；无括号时，有乘除就把所有“两边都是数”的乘除一起算，否则算最左的加减。原为“整数；负数、除不尽、小数报错”，2026-11-27 起支持小数与负数，见下文“小数与负数”。
- 直写：`\dengshi*{… \\ …}`，行首等号可写可不写。
- 命令名：`\dengshi` / `\dengshi*`，英文别名 `\stepeq`（KaTeX 不能注册环境，所以不是 `dengshi` 环境）。
- 只写前几步（维护者 2026-11-26）：`steps=N`（不算题目那行）；没写出来的步骤默认每步一个空等号行 `rest=blank`，`rest=cut` 直接截断；语义式、直写都适用。空白横线 `\underline{\hspace{6em}}`，宽度为 **[推论]**。选项解析在 `dengshi/options.ts`，与竖式的 `StyleOptions` 分开。
- 小数与负数（2026-11-27）：
  - 维护者裁决：小数除法除不尽继续报错（提示改用直写）；负数默认允许，负数加括号，`negative=false` 时不允许。
  - 实现（`dengshi/decimal.ts`）：有符号十进制定点数，加减乘精确；除法约分后分母只含因子 2、5 才除得尽。
  - **[推论]** 题目里写的数照原样写回（3.50 不改成 3.5），算出来的数去掉末尾的 0。
  - **[推论]** 负号只在算式开头或紧跟左括号时表示负数，且后面必须是一个数（`-(3+4)` 报错）；写在运算符后面报“负数要加括号”。括号只包着一个负数（如 `(-3)`）视为负数的写法，不算一步“去括号”，题目里的这对括号照原样写回。算出来的负数前面是运算符时加括号，在开头或紧跟左括号时不加。
  - TeX 输出两处修正：除号直接写 `÷`（MathJax 的 physics 宏包把 `\div` 改成了散度 ∇·，Typora 与出图服务都加载了它，0.8.1 的语义式递等式在这两处会把除号画错）；不在括号里的负数包一层花括号，否则 aligned 第二列开头的空组会让负号排成减号。
- **[推论]** 互不影响的几处同一步算（如 25×4+36÷6 → 100+6），与常见课本写法一致，未逐本核对；如需“一步只算一处”，可加开关。

### 10.2 分解质因数树状图（2026-11-26 实现）

维护者定：语义式两种拆法都做，`split=prime`（默认，每步拆出最小质数）/ `half`（尽量对半拆）；质数画圈（`circle`，默认开）；直写逐条写等式；结果算式 `result` 默认关。无样本，画法按常见写法 **[推论]**。

- 实现：`factortree/`（model、options、semantic、parse、render），与短除法共用 `number-theory.ts`。模型为多叉树 `FactorTreeNode { value, children, circled, marks }`。
- 布局：叶子从左到右依次排开，拆开的数居中在最左、最右孩子上方，父子连斜线。
- 直写 **[推论]**：每条拆树上的一个数，相同的数先拆最左边还没拆的；不检查拆得对不对；只有质数叶子画圈；`\err{}`、`\hong{}` 包整个数；不能用 `split`。
- MathML 表达不了，KaTeX 插件只给朗读文字。
- 原题（维护者 2026-11-26）：`problem` 默认开，在上方写原题；`result` 仍写完整等式。直写没有原题。

原始草稿：

```
      36
     /  \
    2   18
       /  \
      2    9
          / \
         3   3
```

- 模型：二叉树 `Tree { value, children?: [Tree, Tree], prime?: true }`，质数叶子可圈出。
- 排版：分层布局，自己画 SVG（规模小，不引入图布局库）**[推论]**。
- 生成器：给一个数，按从小到大的质因数拆；也允许直写（孩子先拆成 4×9 的另一种树）。

### 10.3 十字相乘法（2026-11-26 实现）

维护者定：二次项系数为 1、不为 1、两个字母三种都做，另做直写 `\shizi*`；画两条交叉斜线；验算行默认写（`check`），分解结果开关 `result` 默认关；右列常数正负号都写。无样本 **[推论]**。

- 实现：`crossmul/`（model、options、poly、semantic、parse、render）。整张图画成 SVG（衬线体、字母斜体），**不是** KaTeX 公式：四个角只支持简单单项式，与下面原始草稿“四角都是 KaTeX 公式”不同。
- 枚举 **[推论]**：a1 取 a 的因数从小到大，c1 按绝对值从小到大、正在前，取第一组 a1·c2 + a2·c1 = b；验算行先左上×右下。
- 报错 **[推论]**：有公因式、二次项系数为负、无常数项时要求先变形；整数范围内分解不了。
- MathML 表达不了，KaTeX 插件只给朗读文字。

原始草稿：

```
   x      +2
     ╲  ╱
      ╳
     ╱  ╲
   x      +3
  ────────────
  3x + 2x = 5x
```

- 模型：`Cross { left: [a1, a2], right: [c1, c2], check?: LaTeX, result?: LaTeX }`，四角都是 KaTeX 公式。
- 生成器：给二次三项式（整系数），枚举分解；无整数分解时报告。
- **[待样本]** 课本里交叉线、验算行（“3x + 2x = 5x”）的画法。

### 10.5 短除法（2026-11-26 实现）

维护者定：第一版做分解质因数（一个数）、两个数的公因数与公倍数、三个数的公倍数、直写 `\duanchu*`；除数从小到大取质数；结果算式用开关 `result`，默认不写；画法按常见写法（无样本）。

- 模型：`shortdiv/model.ts`，`ShortDivRow { divisor?, values }`，每个数整个占一格（`ShortDivTerm` 带 marks），最后一行无除数；`result` 为结果算式文字。与竖式的 `Layout` 分开，自己的渲染器 `shortdiv/render.ts`。
- 三个数【推论】：用能整除其中至少两个数的最小质数去除，除不尽的原样落下，除到两两互质（求最小公倍数的常见写法）。只求三个数的最大公因数（三个都要能整除）未做。
- 结果算式【推论】：`36 = 2×2×3×3`；`(36, 48) = 2×2×3 = 12`、`[36, 48] = 2×2×3×3×4 = 144`；三个数只写 `[…]`，乘积省略 1。圆括号、方括号记号是否合沪教版用法待核。
- 直写：`2 | 36 48 \\ … \\ 3 4`，`\err{}`、`\hong{}` 包整个数；不支持 `result`。
- MathML：表达不了，KaTeX 插件的隐藏 MathML 只给朗读文字（`<mtext>`）。
- 报错：质数、互质、超过三个数、小于 2、大于 100 万。

- 递等式、十字相乘、树状图：暂无样本。

## 12. 语义式（2026-11-25 实现）

维护者定：先做语义式，显示风格由开关控制。实现在 `packages/core/src/semantic/`，产出与直写布局同一模型，共用渲染器。

| 运算 | 范围 | 算法要点 |
|---|---|---|
| 加法 | 整数、小数 | 定点 bigint；进位记在进到的那一列；`padZero` 补齐小数位并标“补 0” |
| 减法 | 整数、小数，结果非负 | 逐列借位，被借的高一位打退位点（跨 0 自然得到“每位各一点”） |
| 乘法 | 整数 | 一位数：`mode=compact`（进位小字，最高位进位直接写进积）/ `expanded`（每位分别乘，带 0）；多位数：非 0 乘数位各一行部分积、左移；`multiCarry` 各组进位（第一组在横线前，之后在各自部分积上方）；`colorByDigit` 按乘数位着色 |
| 小数乘法（2026-11-26） | 小数因数末尾不为 0（2026-11-27 起末尾有 0 也支持） | 两个因数末位对齐，按整数乘（`gap-point.ts` 的空隙小数点）；积 `fromScaled` 补前导 0；`strikeZero`、`markPoint`；进位照整数规则（`carry` 总开关） |
| 小数除法（2026-11-26，`div-decimal.ts`） | 能除尽 | 除数化成整数（被除数补 0 加框【推论】，原小数点 `point: "hua"`）；按位除到余数为 0 且被除数用完；第一步就要用到被除数之外的位、或被除数无小数点而商有小数时往被除数后添 0（“12.0”）；之后添的 0 只在余数行（`markAppended`）；商的整数部分与小数点后不够商的位补 0；除不尽（化简后的除数含 2、5 以外的因数）报错 |
| 除法 | 整数被除数与除数 | 商从第一个够除的位起；余数落位后仍不够除则商 0、不写乘积；最后一行是余数（整除写 0） |
| 孩子的答案 | `a op b = 答案`，除法可带 `……余数` | 照写孩子的答案，与正确答案同列不同的位标 `err`；漏写的位补空格子标 `err`；数值不对却无一位可标时整行标；**默认不画过程**（`process=auto`，2026-11-25：程序按正确算法画的进位、退位点会被误当成孩子写的；补的 0 同样归 `process` 管，维护者定），`process=show` 可强制画出作对照 |

**已确认（2026-11-25，维护者补样本与裁决）**：
- 因数末尾有 0（样本“用一位数乘-末尾有0”，380×3）：0 前面的数对齐，0 甩在外面不参与计算，积末尾再添 0；进位按 0 前面的数算（380×3 的进位 2 在百位）。乘数末尾有 0（25×30）、两个都有（120×30）同此规则。已实现，原“跳过 0 位再写一行积”的做法作废。
- 循环小数与近似值（维护者 2026-11-27 定）：默认除到循环节完整一遍且至少 3 位（`places=N` 改位数），商后写省略号（`repeatDot` 改用循环点，只除一个循环节）；`round=N` 求近似值，竖式除到第 N+1 位，下面一行“≈ 近似值”；循环小数、近似值的孩子答案暂不支持（报错）。布局模型新增格子内容 `ellipsis`、标记 `xun`（循环点）、运算符 `≈`；SVG、MathML（`<mo>…</mo>`、`mover`、`<mo>≈</mo>`）、朗读文字都已支持。**[推论]** 循环节超过 30 位报错要求写 `places`；`places` 上限 30、`round` 上限 10；`repeatDot` 时 `places` 短于一个循环节报错；`round` 遇到本来就能除尽且位数不超过 N 的题照常画、不写 ≈；“≈”一行放在竖式最下面，运算符位置与“×”“+”相同；`remainder` 与 `round` 同用报错。
- 小数因数末尾有 0（3.50×12，维护者 2026-11-27 定）：照上一条，0 甩在外面，按 35×12 算，积按原来的小数位数点小数点（42.00），末尾的 0 划掉；孩子的答案省略末尾的 0 不判错。**[推论]** 无课本样本；因数是 0.0 时按 0 处理。
- 三位数乘一位数（样本“用一位数乘-三位数”，329×4）：课本用简写，与 `mode=compact` 一致。分步式只是两位数时的过渡写法；`mode=expanded` 仍保留为可选，多位数时的写法无课本依据。
- 整数除以整数除不尽：维护者 2026-11-26 定**默认除成小数**；`remainder` 写余数；孩子的答案写了余数时自动按余数画；整除时两种写法相同，走余数写法。
- 直写布局的小数点仍占列（加减法写法），未改；小数乘除的空隙小数点只在语义式里产出。
- MathML：空隙小数点与前一位合成一格（`<mrow><mn>4</mn><mn>.</mn></mrow>`）。polyfill 对照页对齐正确，但不画 `menclose`（划掉的小数点显示为普通小数点），`msrow` 内的 `mathcolor` 也照旧丢失；按 §7 的定论不为 polyfill 调整。
- 小数结果末尾的 0：维护者定**划掉**，新增 `strikeZero`（默认开），加减法都适用；孩子写的答案不划。小数部分全是 0（如 5.00）时只划 0，**小数点不划**（维护者 2026-11-25 定）。

## 13. Typora 插件（2026-11-26 实现）

**维护者裁决（2026-11-26）**：
- 触发写法用公式：本库命令单独写成一个公式（`$$\shushi{…}$$`、`$\shushi{…}$`），和 KaTeX 写法一致，同一份 Markdown 换到 KaTeX 网站也能显示；不用代码块。
- 只做 typora-community-plugin 插件，不做独立安装包。
- 先自用，GitHub Releases 发 `plugin.zip`；稳定后再上架插件市场。
- 代码放本仓 `packages/typora`（private，不发 npm），直接用 workspace 里的 core。

**接入方式（已核实 Typora 1.14.16 与 typora-community-plugin 核心 2.10.21；2026-11-27 维护者在核心 2.10.86 上复测通过）**：
- Typora 的公式块、行内公式、悬浮预览、目录、导出都调 `MathJax.tex2svg` / `MathJax.tex2svgPromise`，“复制为 MathML / 复制到 Word”调 `MathJax.tex2mml`，传入的都是公式原文。插件把这三个入口包一层：整个公式是本库命令时由 core 画 SVG，包成 `<mjx-container jax="SVG">`（Typora 的居中、边距、导出缓存都挂在它上面）；`\dengshi` 先转成 TeX 再交回 MathJax；其余原样交给 MathJax。
- 写法错误显示为红字，元素带 `data-mml-node="merror"`（Typora 用它判断公式出错）。复制 MathML 时竖式给 mstack，其他写法只给朗读文字。
- MathJax 按需加载，改公式设置时会重新加载、入口换新，所以插件每秒检查一次，发现没包过的就包上；包上后清掉 Typora SVG 缓存里的本库命令，调 `File.editor.mathBlock.forceRefresh()` 与 `File.editor.mathInline.renderAll()` 重画已有公式。
- 【推论】和普通公式混写（如 `74+88=162 \quad \shushi{…}`）第一版不支持，报“本库命令要单独写成一个公式”。MathJax 认不出本库命令，要混写得给 MathJax 写 TeX 扩展，等有需要再做。（2026-11-27 已做，见下条。）
- 混写（2026-11-27 实现）：维护者定竖式等**上下居中对着公式中线**。实现在 core `formula/mathjax-embed.ts`，出图服务（`cmn-tex.ts`，TeX 宏包 `cmn`）与 Typora 插件（`tex-extension.ts`）共用。
  - 竖式等：宏在公式里放 `<mrow class="cmn-embed"><mspace/></mrow>`，mspace 的宽、高、深按本库 SVG 尺寸与中线（基线上方 0.25em）算；SVG 与原命令以 base64 放在 `data-cmn-svg`、`data-cmn-tex`。MathJax 排完后 `inlineEmbeddedSvg` 在这个 `<g>` 里插入翻转过的内联 SVG（颜色跟随文字），去掉 data 属性；`embedMathML` 在“复制为 MathML”时把盒子换成本库的 MathML（竖式为 mstack）。
  - 不用图片字形 mglyph：Typora 的 MathJax 加载了 `ui/safe` 且禁止 `data:` 协议，会删掉图片地址，MathJax 随后抛 `RangeError: Invalid code point`（用 Typora 自带的 MathJax4/tex-svg-full.js 与同样配置实测）；出图服务的 resvg 画嵌入图片时也不用内置字体。
  - 递等式：转成的 TeX 放回输入由 MathJax 接着排。**[推论]** 改用 `aligned[t]`，第一行对齐基线（居中时 `S=\dengshi{…}` 会排成“S = = …”）。
  - 写法错误：抛 MathJax 的 TexError，显示为公式里的报错。
  - Typora 注册用的是 MathJax 组件版内部对象（`MathJax._.input.tex.TokenMap.CommandMap`、`TexError`、TeX 输入的 `parseOptions.handlers.add`）；找不到时退回原报错并在控制台警告。KaTeX 插件本来就能混写，不受影响。
- 【推论】行内竖式按 `vertical-align: middle` 对齐。

**风险**：以上都是 Typora 未公开的内部接口，Typora 升级后可能失效。对策：找不到 MathJax 入口（页面上有公式、30 秒后仍找不到）或找不到刷新入口时在控制台警告，不悄悄失效；说明里写清已验证的版本；每次升级 Typora 后打开手测文档 `packages/typora/test/typora-sample.md` 看一眼。

## 14. 出图服务（2026-11-27 实现）

**维护者裁决（2026-11-27）**：
- 接口 GET 与 POST 都给：`GET /render.svg|png?tex=…` 可以直接当图片链接；`POST /render`（JSON）适合长公式和程序调用。
- 递等式也出图：服务端接 MathJax 4（`@mathjax/src`，SVG 输出，字形是路径）。
- PNG 用 resvg（`@resvg/resvg-js`）转，字体内置在仓库里，不读系统字体，任何机器出图一致。
- 放本仓 `packages/server`（private，不发 npm），bun 直接运行，附 Dockerfile；默认只监听本机，不做鉴权，限制公式长度（2000 字符）、`size`（8～128 px/em）、出图边长（4096 px）、请求体（64 KB）。

**实现要点**：
- 【推论】普通公式也交给 MathJax 出图（既然已经接了 MathJax）。
- 【推论】整式识别（原在 Typora 插件里）挪进 core：`translateFormula`、`translateFormulaMathML`、`parseFormulaCommand`、`mentionsFormulaCommand`，Typora 插件与出图服务共用。core 公开接口因此增加，下次发 npm 时升小版本。
- 尺寸：core 的 SVG 按 em 换算（1em = FONT_SIZE 个 viewBox 单位），MathJax 的按 viewBox（1000 单位 = 1em）换算，不用它标的 ex（随字体变）。根元素的 width / height / style 换成像素尺寸与 `color`，SVG 单独打开时也对。
- 颜色参数只放行十六进制色值和英文颜色名，因为会写进 SVG 属性。
- MathJax 宏包与 Typora 一致（维护者 2026-11-27 定：全部加载）：Typora 用 tex-svg-full（默认 base、ams、newcommand、textmacros、configmacros，其余用到时自动加载）并追加 physics；服务端没有组件加载器，一开始就全部导入。【推论】不加载 texhtml、html（能往 SVG 写 HTML、`\href`、`\style`，对外服务有注入风险），不加载 noerrors、noundefined（错误返回 400，不画成红字），require、autoload、colorv2、fontsizev3 也不加载。
- 代码审查（2026-11-27）后的修正：每个请求新建 MathJax 文档（共用一份时 `\newcommand{\frac}` 会污染之后所有请求，新建约 9 ms）；不加载 action（lite 适配器上抛内部错误）；输出统一经 `svg-sanitize.ts` 清理（所有属性值转义 `<` `>`，去掉外部 href，删掉 style 里带 url( 等的声明），因为 `\color`、`\unicode`、`\bbox`、`\mmlToken` 都会把用户文字抄进属性；【推论】带编号的公式（`\tag`）直接返回 400，MathJax 的编号是随容器宽度自适应的结构，单独成图会被裁掉。
- MathJax 的输出要做两处清理：字形编号 `MJX-<计数>-…` 每转换一次加一，换成固定前缀，否则同一请求每次字节不同；`data-latex` 属性抄了公式原文但不转义 `<`，`a<b` 会得到非法 XML、PNG 出错，直接去掉。

**字体（resvg 2.6 实测）**：
- core 的 SVG 数字用根元素上的无衬线字体，变量是 `<tspan font-style="italic">`，结果行有“商”“余数”等中文。
- resvg 在一行里遇到当前字体缺的字，会整行改用能覆盖全部字的字体，斜体 tspan 也变直立（单独给 tspan 指定字体也没用）；中文字体自带的 × 是全角宽度。
- 所以无衬线用 Noto Sans 西文字形 + Noto Sans SC 中文字形合并成“CMN Sans”（常规体、斜体各一），衬线用 STIX Two Text；均为 OFL。常规体的中文覆盖 core 用字 + GB2312 一级常用字 + 全角标点（维护者 2026-11-27 定，`\text{米}` 等单位要用），斜体只带 core 用字；core 新增中文时重跑 `bun run fonts`。字体里没有的汉字（二级字等），PNG 请求返回 400 并列出缺的字，不悄悄画成空白。
