# cn-math-notation 设计草案

日期：2026-11-19　状态：**草案；第一期整数竖式的写法已按沪教版样本核对（§11）**

**定位（维护者 2026-11-19 定）**：中国中小学数学写法库，作为 **KaTeX 的扩展**。普通公式一律交给 KaTeX；本库只做通用工具画不了的课堂写法，要求简单、适合孩子学习。

**范围**：竖式家族（整数与小数加减乘除、多项式竖式、综合除法）、短除法、分解质因数树状图、十字相乘法、递等式。第一期只做整数竖式。

## 0. 与 KaTeX 的关系

**写法用 LaTeX 命令**，在 `$...$` / `$$...$$` 里与普通公式混写：

```latex
$$\shushi{365+278}$$                         % 竖式，程序算出正确过程
$$\shushi[steps]{725\div 4}$$                % 逐步展示
$$\duanchu{36, 48}$$                      % 短除法
$$\shuzhuang{36}$$                        % 分解质因数树状图
$$\shizi{x^2+5x+6}$$                      % 十字相乘
\begin{dengshi}                           % 递等式
  & 25 \times (40 + 4) \\
= & 25 \times 40 + 25 \times 4 \\
= & 1100
\end{dengshi}
```

直写布局（孩子的错误过程等）用环境，沿用 LaTeX `array` 的 `&` 分列、`\\` 分行、`\hline` 画线，格内用小命令挂标记：

```latex
\begin{shushi}
   & 4\tui & 0\tui & 3 \\
 - & 1     & 6     & 7 \\ \hline
   & 3     & 4     & \err{6}
\end{shushi}
% \tui = 退位点，\jin{1} = 进位 1，\err{} = 标为错误
```

命令名**拼音为主、英文做别名**（维护者 2026-11-19 定）。两者完全等价，文档与示例用拼音：

| 拼音（主） | 英文别名 | 写法 |
|---|---|---|
| `\shushi` / `shushi` 环境 | `\vertical` / `vertical` | 竖式 |
| `\duanchu` | `\shortdiv` | 短除法 |
| `\shuzhuang` | `\factortree` | 分解质因数树状图 |
| `\shizi` | `\crossmul` | 十字相乘 |
| `dengshi` 环境 | `stepeq` | 递等式 |
| `\jin{1}` | `\carry{1}` | 进位标记 |
| `\tui` | `\borrow` | 退位点 |
| `\err{}` | `\err{}` | 标为错误（本身是英文缩写，不另设） |

**不设拼音首字母缩写**（维护者 2026-11-19 定：缩写多与 KaTeX/LaTeX 冲突，如 `\ss`=ß、`\j`=ȷ、`\t`=连音符，且树状图与十字相乘同为 `sz`）。只有全拼与英文别名两套。

英文别名的具体拼写 **[待定]**，上线前统一检查是否与 KaTeX 已有命令冲突。

**接入方式（已核实 KaTeX 0.19.1 包内容，2026-11-19）**：
- KaTeX 对外暴露 `__defineFunction`（注释：新增函数，产生解析树节点并有自己的 HTML / MathML 构建器）与 `__defineMacro`；官方 mhchem 扩展用的是 `__defineMacro`。
- KaTeX 本身**没有** `longdiv`、`\enclose` 之类命令，竖式无法只靠宏拼出来。
- 所以用 `__defineFunction` 注册本库命令：HTML 构建器嵌入本库渲染结果，MathML 构建器输出能对应的 MathML 子集。
- 风险：双下划线前缀，按惯例属不稳定接口 **[推论]**。对策：KaTeX 版本锁定在验证过的范围；适配层做薄；跨版本测试。退路：渲染前先扫出本库命令自己画、其余交给 KaTeX（兼容任意版本，但不能嵌进其他公式内部）。

**分包**：
- `core`：模型、生成器、SVG 渲染、朗读文字；不依赖 KaTeX。格子里的公式（如 `3x^2`）通过注入的“公式渲染器”接口画。
- `katex`：KaTeX 插件，注册命令，并把 KaTeX 作为 `core` 的公式渲染器。
- **更正（2026-11-25）**：原写“多数 Markdown 工具已内置 KaTeX，有 `katex` 包就够”，说过头了。KaTeX 插件只在**能控制 KaTeX 加载代码**的地方生效（自己的应用、自建网站）；Typora、Obsidian、GitHub 自带封闭的公式引擎，无法注册新命令。
- **Typora（维护者 2026-11-25 定）**：KaTeX 插件完成后，基于 typora-community-plugin 另写一个 Typora 插件（维护者已有 typora-plugin-plantuml 等经验）。已核实本机 Typora.app 内置的是 **MathJax4**（`Contents/Resources/TypeMark/lib/MathJax4`），不是 KaTeX，所以 Typora 插件直接用 `core` 渲染，不经 KaTeX 插件；接入方式（拦截公式渲染，或用代码块）待做时再定。
- 其他编辑器（Obsidian 等）以后按需各写插件，或提供“渲染成图片”的兜底。

以下 §1～§9 原为竖式的内部模型，仍适用于竖式家族与短除法；树状图、十字相乘、递等式不是格子结构，模型另写（见 §10）。

依据：
- 起源：一个家庭学习项目需要在错题和题目里展示竖式。最初的设想是竖式用带类型的代码块、结构化数据，由渲染器画出；小学三年级的重点就是笔算乘除，出题和展示孩子的计算过程都要用。
- MathML 3 §3.6 / MathML 4 草案 §3.6 / MathML Core（2026-11-19 核实）：竖式元素不在 Core，浏览器不原生渲染；结构可表达多数国内写法，但没有竖线、括号，不支持短除法、综合除法。
- 维护者要求：要考虑初中、高中的扩展；MathML 的默认写法不是国内习惯（加法进位写下标、减法退位打点）。

标注约定：**[推论]** 是 AI 的设计判断，未经实测或样本核对；**[待样本]** 须等沪教版样本确认。

## 1. 目标与不做

目标：
1. 写起来像 LaTeX：短、能手写，嵌在 Markdown 代码块里。
2. 覆盖小学到高中的竖式类写法（清单见 §6），新增写法主要是加“生成器”，模型与渲染器不动。
3. 写法样式可切换：默认沪教版，其他地区、其他教材作为样式预设。
4. 能画**任意过程**，包括孩子的错误过程（不只是程序算出的正确过程）。
5. 可导出 MathML（能对应的子集）。

不做：
- 普通公式（交给 KaTeX）。
- 几何图形、数轴、钟面（另议）。
- 出题、判对错（属计算题引擎 B，待定）。

## 2. 分层

```
 文本写法（人写）          JSON（机器写，例如将来的计算题引擎）
      │                          │
      ▼                          │
 解析 ──► 语义式？──是──► 生成器 ──┤
      │                          │
      └──否（直写布局）──────────►┤
                                 ▼
                           布局模型（Layout）  ◄── 本文主体
                                 │
                  样式预设（cn-hujiao 等）
                                 │
                 ┌───────────────┼───────────────┐
                 ▼               ▼               ▼
              SVG 渲染      朗读文字描述      MathML 导出（子集）
```

- **语义式**：只写算式，如 `403-167`，由生成器算出完整的正确过程。
- **直写布局**：逐行写出格子内容和标记，用于孩子的错误过程、课本上的特殊写法、生成器还不支持的写法。
- 两条路最终都产出同一个布局模型；渲染器只认布局模型。

**[推论]** “朗读文字描述”是额外收益：给孩子用的界面常需要朗读，竖式画成图后屏幕阅读器读不出，所以渲染时同时生成一段可读文字（“三百六十五加二百七十八，个位五加八得十三，写三进一……”）。

## 3. 布局模型

### 3.1 坐标

- **列号**是整数，以个位为 0，向左（高位）为正，向右（小数位）为负：百位 2、十位 1、个位 0、十分位 −1。
  与 MathML 的 `position`（正数向高位）方向一致，便于导出。
- **小数点**不占列，是挂在“第 0 列和第 −1 列之间那条格线”上的标记。
  **[样本已核，§11]** 课本里小数点与数字间距相同，等于占一列。改回 MathML 做法：小数点占一列（列宽可略窄），列号仍以个位为 0，小数点列不计号、由渲染器插在第 0 与 −1 列之间。
- **行号**自上而下，从 0 开始。

### 3.2 元素

| 元素 | 作用 | 主要字段 |
|---|---|---|
| `Figure` | 一个完整竖式 | `kind`（add / sub / mul / longdiv / shortdiv / polydiv / synthdiv / custom）、`rows`、`rules`、`brackets`、`steps`、`style`、`meta` |
| `Row` | 一行 | `role`（operand / result / partial / step / remainder / quotient / divisor）、`cells`、`operator`（行首运算符，如 `+` `×`）、`shift`（整体左右移的列数） |
| `Cell` | 一格 | `col`、`content`（见 3.3）、`marks`、`decor` |
| `Mark` | 格子周围的小标记 | `role`（carry / borrow / note / hint）、`content`、`at`（九方位，可省）、`size`（默认 small） |
| `Rule` | 线 | `dir`（h / v）；横线：`afterRow`、`fromCol`、`toCol`、`overhang`；竖线：`betweenCols`、`fromRow`、`toRow`；`weight` |
| `Bracket` | 除法括号 | `type`（longdiv / shortdiv）、覆盖的行列范围 |
| `Step` | 逐步展示的一步 | `id`、`reveals`（本步出现的元素引用）、`say`（这一步的朗读文字） |

**关键设计：标记存“角色”，位置交给样式。**
`Mark` 只写 `role: carry`，不写位置；沪教版样式规定加法进位画在哪一行、哪个方位、多大。课本换写法，只换样式预设，数据不动。需要例外时，`at` 显式覆盖。
这正是 MathML 的痛点：它把 `location` 写死在数据里，所以“不是国内习惯”只能改数据。

**和 MathML 的差别**（有意为之）：
- 进位挂在**它所属的格子**上，而不是像 `mscarries` 那样挂在“下一行”。
- 有竖线与括号（短除法、综合除法、长除法的括号必需）。
- 有 `Step`，可逐步展示、做动画、朗读。

### 3.3 格子内容

| 类型 | 例 | 说明 |
|---|---|---|
| `digit` | `7` | 一位数字 |
| `term` | `3x^2`、`-5` | 一项，整体占一列；内部用 LaTeX 子集，交给 KaTeX 排 **[推论]** |
| `text` | `余` | 少量文字 |
| `blank` | | 占位但不显示（多项式缺项、对齐用） |
| `box` | `□` | 填空格，给出题用 |

### 3.4 装饰（decor）

划掉（`strike`：斜、反斜、竖、横，可叠加，沿用 MathML 的四种）、圈、框、**高亮**（语义色：`error` / `focus`），用来标出孩子出错的那一位。

### 3.5 错误过程

- 直写布局：孩子怎么写就怎么记，渲染器不校验对错。
- 语义式 + 声明孩子答案，如 `403-167=346`：生成器只能画正确过程，无法知道孩子怎么算的，所以只把结果行标为 `error` 高亮，不编造过程。
- **预留钩子**：`bug=<规则名>` 让生成器按某种错误做法生成过程（规则来自将来的错误做法库）。B 未定，本组件只预留字段，不实现。

## 4. 文本写法（初稿，已被 §0 的 LaTeX 命令写法取代，保留作对照）

原设想 Markdown 里用代码块，语言名 `shushi`。

### 4.1 语义式

````markdown
```shushi
365 + 278
```

```shushi style=cn-hujiao steps
725 ÷ 4
```

```shushi
短除 36 48          # 求最大公因数时的短除法
```

```shushi
(x^2 + 3x + 2) ÷ (x + 1)
```
````

选项：`style=`（样式预设）、`steps`（逐步展示）、`show=`（只画到某一步）、`bug=`（预留）。

### 4.2 直写布局

一行一行写，空格分列，右对齐到个位；`^` 开头的行是挂在上一行的标记行；`---` 是横线。

````markdown
```shushi layout
    4  0  3
^   ·  ·          # 退位点（role=borrow），挂在被减数上
-   1  6  7
---
    3  4  6  !    # 行尾 ! 表示整行高亮为 error（孩子的答案）
```
````

**[推论]** 直写语法是最不确定的部分：要兼顾好写和不歧义（标记对哪一列、多位数标记如“10”）。先用样本里的 10～15 个例子试写，再定。

### 4.3 JSON

机器生成或导出时用 JSON，结构与 §3 一一对应。文本写法解析后也得到同一份 JSON，测试对 JSON 断言。

## 5. 示例（布局用简化 YAML 示意）

### 5.1 加法连续进位：365 + 278 = 643

```yaml
kind: add
rows:
  - role: operand
    cells: [{col: 2, d: 3}, {col: 1, d: 6}, {col: 0, d: 5}]
  - role: operand
    operator: "+"
    cells:
      - {col: 2, d: 2, marks: [{role: carry, content: 1}]}   # 十位进到百位的 1
      - {col: 1, d: 7, marks: [{role: carry, content: 1}]}   # 个位进到十位的 1
      - {col: 0, d: 8}
  - role: result
    cells: [{col: 2, d: 6}, {col: 1, d: 4}, {col: 0, d: 3}]
rules:
  - {dir: h, afterRow: 1}
```

进位记在**第二个加数**的格子上；**[已定，§11.1]** 小字、红色、坐在横线上；位置支持“正下”（沪教版默认）与“左下”两种。

### 5.2 减法跨 0 退位：403 − 167 = 236

被减数百位、十位各带一个 `borrow` 标记，内容是点 `·`。
**[已定，§11.1]** 只打点：百位、十位各一个退位点，0 上方不另写 9。

### 5.3 两位数乘两位数：36 × 24 = 864

```
      3 6
  ×   2 4
  ───────
    1 4 4     ← partial，shift 0
    7 2       ← partial，shift 1（个位空着）
  ───────
    8 6 4
```

**[样本已核，§11]** 两位数乘两位数：部分积不写进位、第二行末尾不补 0（空着）。一位数乘的简写：进位与加法同样画在左下小字。

### 5.4 除法有余数：725 ÷ 4 = 181……1

```
          1 8 1        ← quotient 行，商对齐被除数的位
       ┌───────
     4 │ 7 2 5         ← divisor 在左，Bracket(longdiv) 包住被除数
         4
         ─             ← 每步一条短横线，fromCol/toCol 只覆盖该步
         3 2
         3 2
         ───
             5
             4
             ─
             1         ← remainder
```

除数占被除数左边的列（如 col 4），中间以括号隔开；商、被除数、各步在同一套列号里对齐。
**[样本已核，§11]** 沪教版确为除数在左、商在上，与 MathML 给中国标的 `righttop` 不符。

### 5.5 小数加法：3.45 + 12.6

按小数点对齐。**[样本已核，§11]** 被减数位数不够时补 0，补的 0 用红色虚线框标出（教学标记）；加法样本未见补 0。

### 5.6 短除法求最大公因数：36 和 48

```
   2 │ 36   48
     └──────────
   2 │ 18   24
     └──────────
   3 │  9   12
     └──────────
        3    4
```

每行左侧一条竖线 + 下方一条横线（`Bracket type: shortdiv`）。每个数是一个 `term`（整个数占一格，不按位拆）。**MathML 无法表达，导出时降级。**

### 5.7 初中：多项式长除法 (x² + 3x + 2) ÷ (x + 1) = x + 2

结构与 5.4 相同，只是格子内容是 `term`（`x^2`、`+3x`、`+2`），列按次数对齐（x² 列、x 列、常数列）；缺项用 `blank`。生成器不同，模型不变。

### 5.8 高中：综合除法，除以 x + 1

```
  -1 │  1    3    2
     │      -1   -2
     └──────────────
        1    2 │  0
```

用竖线、横线和 `term` 即可表达，最后一格前的竖线隔出余数。**MathML 无法表达。**

## 6. 写法清单与分期

| 期 | 写法 | 生成器 | MathML 导出 |
|---|---|---|---|
| 一 | 整数加、减（含连续进位、跨 0 退位）、乘（一位、两位）、除（一位除数、有余数） | 有 | ✓ |
| 一 | 直写布局（任意过程，含错误过程） | 不需要 | 部分 |
| 二 | 小数加减乘除；两位数除数 | 有 | ✓ |
| 二 | 短除法（分解质因数、最大公因数、最小公倍数） | 有 | ✗ 降级 |
| 三 | 多项式乘法、长除法；分离系数法 | 有 | ✓（按项对齐） |
| 三 | 综合除法、进制转换短除、辗转相除 | 有 | ✗ 降级 |

非格子类写法（见 §10）：递等式、树状图排第二期，十字相乘排第三期。

逐步展示（`steps`）与朗读文字建议第一期就做 **[推论：模型里有 Step，生成器顺手产出，成本不大]**。

## 7. MathML 导出对应

| 本模型 | MathML |
|---|---|
| Figure（add/sub/mul） | `mstack` |
| Figure（longdiv） | `mlongdiv`，`longdivstyle` 由样式决定 |
| Row + shift | `msrow position` / `msgroup shift` |
| Mark(carry/borrow) | `mscarries` + `mscarry location`（从“所属格”换算成“挂下一行”） |
| strike | `crossout` |
| 横线 | `msline length position` |
| term | 一列内的 `mrow` |
| 竖线、shortdiv 括号、高亮、Step | 无对应 → 降级（导出 SVG 图片或省略并给出提示） |

## 10. 非格子类写法（初稿）

### 10.1 递等式（脱式计算）

- 本质是“等号对齐的多行”，KaTeX 的 `aligned` 已能排；本库只包一层国内格式：首行不写等号，后续每行以 `=` 开头并对齐。**[待样本]** 沪教版是等号对齐首行算式左端，还是等号悬在左侧。
- 模型：`StepEq { lines: [{ expr: LaTeX, note? }] }`，每行可挂 `err` 高亮，可逐行展示（复用 `Step`）。
- 生成器（以后）：按运算顺序把算式逐步化简，可用于展示“先乘除后加减”。
- 成本最低，可与第一期并行做。

### 10.2 分解质因数树状图

```
      36
     /  \
    2   18
       /  \
      2    9
          / \
         3   3
```

- 模型：二叉树 `Tree { value, children?: [Tree, Tree], prime?: true }`，质数叶子可圈出。
- 排版：分层布局，自己画 SVG（规模小，不引入图布局库）**[推论]**。
- 生成器：给一个数，按从小到大的质因数拆；也允许直写（孩子先拆成 4×9 的另一种树）。

### 10.3 十字相乘法

```
   x      +2
     ╲  ╱
      ╳
     ╱  ╲
   x      +3
  ────────────
  3x + 2x = 5x
```

- 模型：`Cross { left: [a1, a2], right: [c1, c2], check?: LaTeX, result?: LaTeX }`，四角都是 KaTeX 公式。
- 生成器：给二次三项式（整系数），枚举分解；无整数分解时报告。
- **[待样本]** 课本里交叉线、验算行（“3x + 2x = 5x”）的画法。

## 12. 语义式（2026-11-25 实现）

维护者定：先做语义式，显示风格由开关控制。实现在 `packages/core/src/semantic/`，产出与直写布局同一模型，共用渲染器。

| 运算 | 范围 | 算法要点 |
|---|---|---|
| 加法 | 整数、小数 | 定点 bigint；进位记在进到的那一列；`padZero` 补齐小数位并标“补 0” |
| 减法 | 整数、小数，结果非负 | 逐列借位，被借的高一位打退位点（跨 0 自然得到“每位各一点”） |
| 乘法 | 整数 | 一位数：`mode=compact`（进位小字，最高位进位直接写进积）/ `expanded`（每位分别乘，带 0）；多位数：非 0 乘数位各一行部分积、左移；`multiCarry` 各组进位（第一组在横线前，之后在各自部分积上方）；`colorByDigit` 按乘数位着色 |
| 除法 | 整数被除数与除数 | 商从第一个够除的位起；余数落位后仍不够除则商 0、不写乘积；最后一行是余数（整除写 0） |
| 孩子的答案 | `a op b = 答案`，除法可带 `……余数` | 照写孩子的答案，与正确答案同列不同的位标 `err`；漏写的位补空格子标 `err`；数值不对却无一位可标时整行标；**默认不画过程**（`process=auto`，2026-11-25：程序按正确算法画的进位、退位点会被误当成孩子写的；补的 0 同样归 `process` 管，维护者定），`process=show` 可强制画出作对照 |

**已确认（2026-11-25，维护者补样本与裁决）**：
- 因数末尾有 0（样本“用一位数乘-末尾有0”，380×3）：0 前面的数对齐，0 甩在外面不参与计算，积末尾再添 0；进位按 0 前面的数算（380×3 的进位 2 在百位）。乘数末尾有 0（25×30）、两个都有（120×30）同此规则。已实现，原“跳过 0 位再写一行积”的做法作废。
- 三位数乘一位数（样本“用一位数乘-三位数”，329×4）：课本用简写，与 `mode=compact` 一致。分步式只是两位数时的过渡写法；`mode=expanded` 仍保留为可选，多位数时的写法无课本依据。
- 小数结果末尾的 0：维护者定**划掉**，新增 `strikeZero`（默认开），加减法都适用；孩子写的答案不划。小数部分全是 0（如 5.00）时只划 0，**小数点不划**（维护者 2026-11-25 定）。
